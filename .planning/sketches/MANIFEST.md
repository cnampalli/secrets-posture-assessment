# Sketch Manifest

## Design Direction

Stakeholder-facing visualisations of the XYZ Secrets-Management PRD research corpus
(1,597 vendor-capability rows × 19 vendors × 37 NHIs × 47 use cases × 4 regulatory
frameworks). The visual language must read as **credible internal research** — Gartner /
McKinsey adjacent, not consumer SaaS — and survive both interactive HTML viewing and
black-and-white board-pack print paths.

Neutral professional palette, no XYZ brand mirror (Stage 1). Density-tolerant typography,
serif headings for executive gravitas, monospace for IDs / control codes. Colour reserved
for status semantics (RAG / coverage / maturity), never decoration.

## Reference Points

- `matrix/matrix-viewer.html` — existing capability-matrix browser. Palette and coverage
  taxonomy (NATIVE / ADD-ON / PARTNER / GAP / N/A) are reused for continuity.
- Gartner Magic Quadrant single-pagers — vendor scorecard composition cues.
- APRA prudential reporting templates — control-traceability rigour.
- MITRE ATT&CK Navigator — heatmap density precedent.

## Stage 1 Scope (locked by plan)

Three throwaway sketches, one per stakeholder tier. Outcomes feed a Stage-2 decision gate;
no polished production build inside this stage.

## Conventions

- Each sketch is generated by a `build.py` (mirrors `matrix/build_matrix_viewer.py`).
  Run from sketch dir: `python3 build.py` → emits `index.html`.
- All data is inlined into `index.html` at build time. `index.html` is portable
  (file:// works) and offline-capable.
- 2–3 variants per sketch, tab-switched within the single HTML file.
- Shared theme via `<link rel="stylesheet" href="../themes/default.css">`.
- Print CSS exists; every sketch must survive print-to-PDF as a deliverable artifact.
